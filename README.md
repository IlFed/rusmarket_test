# Руссмаркет — график смен

Рабочий редактор расписания по [макетам Figma](https://www.figma.com/design/QVdDSEGTL1bWg7UmuPpoPe/Тестовое-задание-разработчик?node-id=0-1).

React + TypeScript + Vite, REST API на Hono/Node.js, PostgreSQL. Для запуска без внешних сервисов используется PGlite — встроенный движок PostgreSQL с хранением на диске. При наличии `DATABASE_URL` приложение подключается к обычному PostgreSQL через `postgres`.

## Запуск

Нужен Node.js 24+.

```sh
npm ci
npm run dev
```

Интерфейс: <http://127.0.0.1:5173>. API: <http://127.0.0.1:3001/api/health>.

На текущем компьютере также можно запустить `./run.sh`: скрипт найдёт установленный для проекта Node.js, даже если он отсутствует в системном `PATH`.

Первый запуск создаёт пустой график, восемь сотрудников и три шаблона. Начальный период — 1–7 июня 2026 года: понедельник приходится на первое число, как в макете. Год и месяц можно менять в панели над календарём. Данные сохраняются в `data/postgres/`, этот каталог исключён из Git.

## Возможности

- Неделя и полный месяц с горизонтальной прокруткой. Закреплены сотрудники, заголовки и покрытие.
- Поиск по имени или фамилии без учёта регистра, с поддержкой `е`/`ё`.
- Выделение отдельных ячеек, прямоугольной области указателем и диапазона с Shift.
- Назначение шаблона нескольким сотрудникам и датам за одно действие.
- Быстрое назначение через заголовок даты; меню ячейки по двойному или правому щелчку.
- Своя смена с временем начала и окончания, в том числе с переходом через полночь.
- Перенос готовой смены между ячейками и шаблона из правой панели. Используются Pointer Events; назначения также доступны без перетаскивания.
- Изменение и удаление назначенных смен, отмена и повтор последних 50 изменений.
- Расчёт покрытия, количества назначенных шаблонов и часов сотрудника за отображаемый период.
- Сохранение черновика, публикация отдельного снимка графика, обработка ошибок и конфликтов версий.
- Адаптивная компоновка, мобильное меню, управление с клавиатуры, справка.

`Сохранить` отправляет текущий черновик в API. `Опубликовать` атомарно сохраняет черновик и отдельный снимок `published_shifts` с датой публикации. Уведомления сотрудникам или интеграции с внешними сервисами в задании не описаны и не выполняются.

## Проверки

```sh
npm run check         # 11 тестов, TypeScript, production-сборка
npm run format:check
npm audit
```

Тесты используют настоящий движок PostgreSQL/PGlite: сохранение и чтение, перезапуск базы на диске, валидация, конкурирующие версии, независимый опубликованный снимок. Отдельно проверяются границы календаря, ночные смены и массовое назначение.

Тот же набор успешно проверен с PostgreSQL 17 в Docker. Для повторного запуска с внешней **тестовой** базой укажите `TEST_DATABASE_URL` перед `npm test`. Набор очищает график в указанной базе перед каждым API-тестом.

В браузере проверены выделение, назначение шаблонов, собственная смена, перенос сотрудник → сотрудник и шаблон → ячейка, поиск, покрытие, отмена/повтор, навигация, сохранение и повторная загрузка. Эталонная ширина — 1700 px, мобильная — 390 px. Снимки результата находятся в `docs/screenshots/`.

## Production и Docker

```sh
npm run build
npm start
```

Один процесс раздаёт собранный frontend и API на порту 3001. Настройки из `.env` загружаются сервером; пример находится в `.env.example`.

С отдельным PostgreSQL:

```sh
docker compose up --build -d
```

Открыть <http://127.0.0.1:3001>. Compose создаёт PostgreSQL 17 и отдельный постоянный volume. Пароль локальной базы можно задать переменной `POSTGRES_PASSWORD`. Данные не исчезают при обычном `docker compose down`.

| Переменная     | Значение по умолчанию | Назначение                                                |
| -------------- | --------------------- | --------------------------------------------------------- |
| `PORT`         | `3001`                | Порт HTTP-сервера                                         |
| `HOST`         | `127.0.0.1`           | Адрес прослушивания                                       |
| `DATA_DIR`     | `./data/postgres`     | Каталог встроенной базы                                   |
| `DATABASE_URL` | не задана             | URL отдельного PostgreSQL, имеет приоритет над `DATA_DIR` |

Для хостинга достаточно Node.js 24+, `npm ci`, `npm run build`, `npm start` и постоянного диска либо внешнего PostgreSQL. `HOST=0.0.0.0` нужен, если сервер запускается за внешним reverse proxy. Приложение реализует один общий демонстрационный график без авторизации; при размещении рабочих данных требуется добавить аутентификацию и разграничение доступа.

## Устройство проекта

```text
src/
  App.tsx               — экран, навигация и команды редактора
  ScheduleGrid.tsx      — календарь, выделение, клавиатура
  TemplatePanel.tsx     — шаблоны и собственная смена
  useSchedule.ts        — загрузка, сохранение, история изменений
  usePointerDrag.ts     — перенос мышью/указателем
  styles.css            — стили и адаптивные состояния
shared/schedule.ts      — общие типы, календарь и операции со сменами
server/
  app.ts                — API, проверка запросов, конфликты версий
  database.ts           — адаптер PostgreSQL/PGlite и инициализация
  index.ts              — HTTP-сервер и остановка процесса
tests/schedule.test.ts  — 11 тестов
docs/design/            — просмотренные эталоны Figma
docs/screenshots/       — результаты браузерной проверки
```

| Запрос                       | Результат                                         |
| ---------------------------- | ------------------------------------------------- |
| `GET /api/health`            | Проверка соединения с базой                       |
| `GET /api/schedule`          | Сотрудники, шаблоны, смены, revision, publishedAt |
| `PUT /api/schedule`          | Сохранение `{ revision, shifts }`                 |
| `POST /api/schedule/publish` | Сохранение и публикация `{ revision, shifts }`    |

Хранилище использует один агрегат графика с JSONB и номером версии. Обновление выполняется атомарным `UPDATE ... WHERE revision = ... RETURNING ...`: устаревшая версия получает `409`, существующие данные сохраняются. Неизвестные сотрудники, неверные даты, время, дубликаты ячеек и нулевые смены отклоняются до записи. Список сотрудников и шаблоны заданы типизированным справочником, поскольку экран управления этими справочниками отсутствует в задании.
