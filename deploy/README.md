# VPS: отдельная служба на порту 8080

Этот вариант использует Node.js 24 и обычный PostgreSQL 18. Сборка интерфейса
выполняется локально. Docker и изменения существующих reverse proxy не требуются.
Для VPS с 2 ГБ RAM выбран обычный PostgreSQL: инициализация встроенного PGlite
потребовала слишком много памяти для выделенного лимита.

## Размещение

- `/opt/russmarket/releases/<release>` — готовый `dist/`, каталоги `server/`, `shared/`,
  `package.json`, `package-lock.json` и production-зависимости.
- `/opt/russmarket/current` — ссылка на активный релиз.
- `/opt/russmarket/runtime` — отдельный Node.js 24 из официального дистрибутива.
- `/var/lib/postgresql/18/main` — постоянные данные PostgreSQL, отдельно от релиза.
- `/etc/russmarket.env` — `DATABASE_URL` с отдельной учётной записью базы; файл
  принадлежит root и доступен только ему (`0600`), в Git не хранится.
- `/etc/systemd/system/russmarket.service` — копия [russmarket.service](russmarket.service).
- `/etc/systemd/system/postgresql@18-main.service.d/resources.conf` — копия
  [postgresql-resource-limits.conf](postgresql-resource-limits.conf).
- `/etc/postgresql/18/main/conf.d/russmarket.conf` — копия
  [postgresql-russmarket.conf](postgresql-russmarket.conf).

Создаётся системный пользователь `russmarket` без интерактивного входа. Код принадлежит
root; файловая система для приложения доступна только для чтения, кроме временных файлов.
Зависимости устанавливаются через `npm ci --omit=dev --ignore-scripts` по lock-файлу.
Сервер запускается напрямую через Node.js, без Vite, watcher и `tsx`.

Предел памяти приложения — 256 MiB, базы — 256 MiB; мягкий порог каждой службы —
192 MiB. Приложение ограничено половиной одного ядра, база — четвертью ядра.
Автоматический перезапуск приложения ограничен пятью попытками за две минуты.
PostgreSQL слушает только `127.0.0.1:5432`, использует 64 MiB shared buffers и не
более 20 соединений. Приложению принадлежит отдельная база `russmarket`.

## Доступ

Приложение слушает `8080/TCP`. Для UFW добавляется только адресное правило:

```sh
ufw allow proto tcp to SERVER_IPV4 port 8080 comment 'Russmarket web demo'
```

Сайт доступен по `http://SERVER_IPV4:8080`. HTTPS в этом варианте не настроен.
Приложение — публичное тестовое демо с одним общим графиком; не размещайте в нём
реальные персональные данные сотрудников.

Существующие службы, VPN, их настройки и правила фаервола не изменяются. Перед запуском
проверяются занятость порта и отсутствие службы с таким же именем. Перед установкой
PostgreSQL проверяется план пакетного менеджера: только новые пакеты, без обновлений
существующих; автоматические перезапуски посторонних служб отключены для этой команды.

## Проверка и управление

```sh
systemctl status russmarket --no-pager
journalctl -u russmarket -n 50 --no-pager
curl --fail http://127.0.0.1:8080/api/health
systemctl restart russmarket
```

После деплоя проверяются загрузка страницы, создание и сохранение смены, публикация,
повторное чтение после перезапуска службы и сохранность состояния существующих служб.

## Обновление и возврат

Подготовьте новый каталог релиза, проверьте зависимости и переключите ссылку `current`
через временную ссылку и `mv -T`. Перезапустите только `russmarket.service`.
При неудаче верните ссылку на предыдущий релиз и перезапустите эту же службу.
База при переключении релизов сохраняется; будущие несовместимые изменения схемы
потребуют отдельного плана миграции и восстановления.

Чтобы отключить приложение:

```sh
systemctl disable --now russmarket
ufw delete allow proto tcp to SERVER_IPV4 port 8080
```

Для согласованной резервной копии базы можно использовать `pg_dump`:

```sh
umask 077
runuser -u postgres -- pg_dump --format=custom russmarket > /SECURE_BACKUP_DIR/russmarket.dump
```

Храните копии вне каталога релиза и периодически проверяйте восстановление в отдельную
тестовую базу. Перезапуск приложения или PostgreSQL не удаляет сохранённый график.
